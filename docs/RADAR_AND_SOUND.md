# Atmos Weather 2.1 — radar and interaction sounds

The Radar tab and dashboard radar card open a native Canvas map centered on the selected city. The precipitation detail page also links to it. Dragging pans; explicit zoom and center controls work without gestures. Previous/Next, a discrete timeline, and Play/Pause show observed radar history. Frame timestamps use the selected city's forecast timezone and the existing AM/PM or 24-hour setting.

Radar follows the current [RainViewer personal API example](https://github.com/rainviewer/rainviewer-api-example): past observations only, Universal Blue PNGs, native zoom capped at 7. It uses no nowcast or satellite layer. Radar coverage varies; an empty tile is not proof of dry weather. The map explains coverage limits, labels delayed observations and saved offline history, and links RainViewer and OpenStreetMap contributor attribution. No precipitation is simulated when the service fails.

Only visible tiles for the selected frame are requested. Four concurrent requests, cancellable OkHttp calls, a 40 MiB HTTP cache, viewport debounce, bounded response sizes and decoded tile dimensions constrain resource use. There is no bulk/offline tile prefetch. HTTP cache headers are respected. Radar metadata refreshes every five minutes while resumed and can fall back to saved metadata less than 24 hours old; tiles remain subject to HTTP cache availability. Offline history is not guaranteed to contain every frame/viewport. Failed tiles show an explicit error, and incomplete radar mosaics are withheld. Playback waits for the selected radar frame to finish, pauses when backgrounded, and is disabled under reduced motion/Minimal; manual stepping remains available. Radar is never fetched by widgets or background workers.

Settings → UI & weather sounds enables nine original synthesized cues: selection, navigation, confirmation, switch, refresh, play, pause, zoom and sculpture. A preview button is included. Weather ambience can be disabled separately while keeping UI cues. SoundPool plays bounded PCM notes with a short rate limit and one stream so rapid scrubbing does not stack sounds. Players are released when backgrounded or disabled. Cues respect normal ringer mode and avoid playing over other media. Ambience retains audio-focus handling and now runs only on the Weather page. No downloaded recordings or extra sound permissions are required.

Application identity, Room schema, weather/widget caches and existing preferences are preserved. Version name is 2.1, version code 3. The new `ambience` preference defaults true to preserve existing sound behavior; the sound master switch remains off by default. Debug signing uses the existing local key; fresh GitHub runners still cannot guarantee signer compatibility with previously installed builds.

Validation includes parser/URL constraints, observed-only frame selection, Web Mercator dateline/polar behavior, original PCM/WAV data, old preference decoding, actual loopback HTTP requests for metadata/cache fallback and cancellation, tile decoding/error limits, Compose radar controls, reduced-motion behavior and explicit service/tile failures. Live `api.rainviewer.com` access was rejected by the cloud proxy (HTTP 403), so no successful live imagery validation is claimed. Real coverage, audio volume/focus, and map performance need phone verification. Required provider hosts on a device are `api.rainviewer.com`, the HTTPS `*.rainviewer.com` tile host returned in its metadata (normally `tilecache.rainviewer.com`), and `tile.openstreetmap.org`.
